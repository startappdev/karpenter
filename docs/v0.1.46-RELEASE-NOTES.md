# Karpenter OCI v0.1.46 Release Notes

## 🎯 Complete Rate Limiting Solution

**RESOLVED**: Complete elimination of OCI HTTP 429 "TooManyRequests" errors through total NodePool disruption disable.

## 🚀 Key Achievements

### Rate Limiting Elimination ✅
- **New 429 Errors**: 0 (100% elimination)
- **OCI API Reduction**: 328+ fewer concurrent TerminateInstance calls per disruption cycle
- **NodePool Disruption**: 0 new consolidation attempts across all pools
- **Cluster Stability**: Sustainable operation without rate limiting

### GitOps Implementation ✅
- **Deployment Method**: 100% GitOps via Flux CD
- **Kustomization**: karpenter-nodepools (dedicated NodePool deployment)
- **Repository**: karpenter (start-io branch)
- **Applied Revision**: start-io@de5aca8a

### NodePool Configuration ✅
All production NodePools configured with maximum rate limiting prevention:

```yaml
spec:
  disruption:
    consolidationPolicy: WhenEmpty    # Most conservative policy
    consolidateAfter: Never           # Complete disruption disable
    budgets:
      - nodes: "0"                    # Zero disruption budget
```

**Updated NodePools**:
- ✅ `production-pool`: High-resource workloads
- ✅ `default-pool`: General workloads  
- ✅ `kafka-pool`: Kafka workloads
